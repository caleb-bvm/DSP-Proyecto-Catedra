# Evidencias verificables

- [Verificación funcional del prototipo](Verificacion-funcional.md): pruebas de reglas/SQL, recorrido HTTP y capturas tras desarrollar los módulos.

- [Verificación inicial](Verificacion-inicial.md): resultado histórico del 8 de octubre de 2026 para esquema SQL Server y páginas informativas.
- [Verificación de reorganización](Verificacion-reorganizacion.md): conservación de archivos, referencias y compilación tras el cambio de carpetas del 12 de octubre.
- [Plan de pruebas y entrega](../fase-2/Pruebas-y-entrega.md): casos pendientes para acreditar el sistema funcional.

Cada nueva evidencia debe indicar fecha, versión/commit, entorno, responsable real, entrada, resultado esperado y obtenido, estado y captura/log asociado. Una prueba pendiente no es una prueba superada.

Conservar solo datos ficticios en las evidencias; ocultar claves en capturas. Los temporales de extracción y las imágenes de lectura de documentos permanecen en `tmp/` y no se contabilizan como pruebas funcionales.
